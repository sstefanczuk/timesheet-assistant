## Phase 3 renewed diagnosis — 2026-11-08

- The user explicitly authorized continuing on `windows-2025` with a fresh limit of two corrections. Existing limits on runner architecture, loopback access and global debug settings remain unchanged.
- Inspection of the installed Playwright driver confirms that HTTP endpoint attachment performs a single `/json/version/` discovery using its proxy-aware HTTP helper, while websocket endpoint attachment bypasses that discovery. The observed failures occurred during this HTTP stage. Proxy involvement is a hypothesis, not established by the logs.
- Renewed correction 1 polls the owned endpoint through a proxy-disabled, redirect-disabled HttpClient, with at most two seconds per request inside the existing total 60-second startup budget. It rechecks listener ownership, validates the returned websocket URL as loopback on the reserved port, then performs one direct websocket attach using the remaining startup time. Only transient HTTP transport/request-timeout failures are retried; UI assertions, malformed discovery, foreign ownership and non-success HTTP responses are not retried. Exited PID-attached processes no longer require an unsafe ExitCode read.
